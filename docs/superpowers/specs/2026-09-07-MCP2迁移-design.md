# MCP 2.x 迁移 — 需求说明书

> **日期** 2026-09-07 ｜ **状态** 已评审（设计获批） ｜ **来源文档** [local-datasource-MCP2迁移方案-2026-09-06.md](local-datasource-MCP2迁移方案-2026-09-06.md)（Quant-Research 项目提出）
> **一句话**：入口层从 mcp 1.x 低层装饰器 API 迁到 2.x 官方高层 API，依赖放开为 `mcp>=2.0.0,<3`，providers 层与 CLI 零改动，与 Quant-Research 共存同一 Python 环境。

---

## 1. 背景与问题

- 本库因 mcp 2.x 移除 1.x 装饰器注册 API，于 commit `6455c77` 钉版 `mcp>=1.6.0,<2` 止血；代价是与需要 mcp 2.x 的项目（Quant-Research）不能共享 Python 环境。
- 当前钉版无实际故障场景，本迁移属消雷性质：一次迁到位，消除未来被动。

## 2. 来源文档核实结论（2026-09-07 实测）

来源文档的全部事实性断言均已核实**属实**，关键三条的硬证据：

| 断言 | 证据 |
|---|---|
| 旧代码在 mcp 2.1.1 下启动即抛 `AttributeError` | 实测：`mcp.server.Server` 类仍在（lowlevel），但 `list_tools`/`call_tool` 装饰器属性被移除，调用即抛 `AttributeError: 'Server' object has no attribute 'list_tools'` |
| 2.x 高层 API 吞业务异常成裸 `Error executing tool <name>` | 2.1.1 源码原文坐实（`mcp/server/mcpserver/tools/base.py:158`）：非 `ToolError` 异常包装为 `UnexpectedToolError`，原文注明 "nothing from the original reaches the client"。本库 `CoverageError` 为 `ValueError` 子类，走此路径——补数指引将到不了客户端，**必须**以文本包装回传 |
| Quant-Research 蓝本可对照 | 蓝本 174 行/4 工具与描述一致；`fe9ed77` 修复提交存在（错误捕获接入 stdio 真实路径） |

来源文档的两处遗漏，本说明书补正：

1. **高层 API 不收手写 InputSchema**：`MCPServer.add_tool()` 的 schema 一律从函数签名经 pydantic 推导，`build_tools()` 的 16 段手写 JSON 无法原样搬入。实测 `Annotated[类型, Field(description=…)]` + `Literal` + 默认值生成的 schema 在 enum/default/required/每参数描述上与手写版**语义等价**，仅多无害 `title` 字段——由此选定"签名驱动"路线（§3 用户决策 1）。
2. **契约回归测试耦合入口形状**：`tests/test_contract_regression.py` import `build_tools()` 并读 1.x 形状的 `t.inputSchema`，必须随迁移改造，"现有 tests/ 全量通过"不是零改动。

## 3. 需求对齐结论（用户决策）

1. **方案 A：签名驱动**（2026-09-07 选定）。16 个工具的 schema 由类型注解单一来源生成，不保留手写 JSON；与 Quant-Research 蓝本同构，共享心智与审查经验。
2. **范围**：只动 `server.py` 入口层 + `pyproject.toml` + `tests/` + 文档；providers 层 16 个数据适配器零改动，`download` CLI 零改动。
3. **契约保真原则**：Agent/客户端可见行为不变优先于代码形态美观（详见 §5.4 保真清单）。

## 4. 功能需求

### 4.1 依赖声明

`pyproject.toml`：`mcp>=1.6.0,<2` → **`mcp>=2.0.0,<3`**。
已验兼容：mcp 2.1.1 `Requires-Python >= 3.10`，与本库 `requires-python = ">=3.10"` 一致。

### 4.2 入口层形态（server.py 重写）

- 16 个薄工具函数经 `@mcp.tool(structured_output=False)` 注册；`structured_output=False` 为**固定要求**——否则返回 `str` 会生成并广播 `output_schema`，与现状（纯文本工具）不符。
- 每个参数用 `Annotated[类型, Field(description=现文)]` + `Literal` 枚举 + 默认值重建 schema；**工具描述文本与参数描述文本从 `build_tools()` 原样搬运，不改写**（沿用"工具描述 ~100 字预算"的既有措辞资产）。
- 工具函数体统一一行转发到 `_safe_summary(name, arguments)`；`_safe_summary` 内部保留现有 16 分支业务分发，异常统一捕获为 `Error calling {name}: {e}` 文本回传——这是 fe9ed77 教训的落法，保证 `CoverageError` 补数指引以文本到达客户端。
- 同步入口 `main()` 的 **`download` CLI 分支必须保留**（`local-datasource download ...` 转交批量下载 CLI；这是"重写入口层"最易丢失的用户可见功能）。

### 4.3 客户端可见契约（保真清单）

以下各项迁移前后**必须一致**（锁定方式见 §5：工具名/required/enum 入契约测试，文本与输出格式在实现期对照旧版核对并由探针覆盖）：

- 16 个工具名（清单见 `tests/test_contract_regression.py` 的 `EXPECTED_TOOL_NAMES`）；
- 各工具 required 字段与枚举值（`kind`/`market`/`period`/`freq`/`adjust` 等 Literal 集合）；
- 参数描述与工具描述文本；
- 错误文本格式 `Error calling {name}: {e}`；
- 调用返回：CSV 落盘路径 + 前 5 行预览（utf-8-sig），格式不变。

### 4.4 已知微漂移（如实记录，不隐瞒）

1. 生成的 inputSchema 比手写版多 `title` 字段（pydantic 自动产物，对 Agent 无语义影响），外层多 `title: "<tool>Arguments"`。
2. `query_yfinance` 的 `use_yfinance`：为保留"缺省回退 config"语义，薄函数签名用 `bool | None = None`，分发层 `None → config.providers.yahoo.use_yfinance`（实测 config 默认 `False`，见 `config.py`）。schema 默认值显示从 `false` 变为 null，实际行为不变。

### 4.5 文档同步

- `README.md`：实测当前无 mcp 版本字样，迁移后如新增表述按 2.x 口径。
- 依赖表述如有 "mcp 1.x"/`<2` 字样一并更新（`pyproject.toml` 之外，来源文档 §5.5 要求）。
- 用户侧 skill 文件（仓库外 `~/.agents/skills/local-datasource/SKILL.md`）无 mcp 版本表述，无需迁移相关改动；其"7 个 tool"计数过时属既有问题，**不在本迁移范围**。

## 5. 测试需求

1. **契约回归改造**：`test_contract_regression.py` 从 `build_tools()` 的 1.x 形状改为对 2.x `list_tools()` 断言（取数方式变，锁定内容不变：工具名集合、required、enum）。
2. **新增 stdio 探针测试**（移植蓝本模式）：subprocess 起服务 → `initialize`（应答含 `serverInfo.name`）→ `tools/list`（16 工具）→ `tools/call`（任选 3 工具真调用）→ **错误指引断言**：构造触发 `CoverageError` 的调用，断言客户端收到完整补数指引文本而非裸 `Error executing tool`。此断言是 fe9ed77 缺陷的长期回归门。
3. providers 层既有测试零改动，全量照跑。

## 6. 验收标准

- [ ] 依赖为 `mcp>=2.0.0,<3`，干净环境安装后 `local-datasource` 可启动；
- [ ] `initialize` 探针应答含 `serverInfo.name`；
- [ ] `tools/list` 列出全部 16 个工具，名称与 `EXPECTED_TOOL_NAMES` 一致；
- [ ] 任选 3 个工具 `tools/call` 真实调用：返回 CSV 落盘路径 + 前 5 行预览，与现有输出格式一致；
- [ ] 构造 `CoverageError` 样例：错误文本（含补数指引）完整到达客户端，不是裸 `Error executing tool`；
- [ ] `local-datasource download` CLI 分支回归可用；
- [ ] 契约回归测试在 2.x 形状上通过；providers 层测试全量通过；
- [ ] README/依赖表述无 1.x 残留。

## 7. 边界与非目标

- 不动 providers 层、cache、CLI、formatters（`handle_call_tool` 的业务分发逻辑原样保留，仅宿主换壳）；
- 不新增/删减工具，不改工具名与参数语义；
- 不做 HTTP/SSE 传输（保持 stdio 单传输）；
- 不改工具描述措辞（即使发现可优化处，另立任务）；
- 不修 SKILL.md 的工具数过时问题（既有问题，另行处理）。

## 8. 风险与回滚

| 风险 | 评估 |
|---|---|
| MCP 客户端兼容性 | stdio + 协议版本协商是 MCP 基本面；Quant-Research 已在 2.1.1 实跑。老客户端若只认 1.x，临时回退钉版分支 |
| schema 生成漂移 | §4.4 两处已知微漂移之外，由契约测试锁定 enum/required/描述文本 |
| 回滚 | 单 PR（server.py + pyproject + tests + docs），`git revert` 整体回滚 |
| 并存期 | 合入前钉版 1.x 现状继续可用，无切换压力 |
